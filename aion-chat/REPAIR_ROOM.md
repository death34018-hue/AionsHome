# 维修室

入口是首页的「维修室」，页面 `/repair`。图标独立保存为 `public/repair-room-icon.png`，目前复制自娱乐室，替换这个文件即可。

工作模型默认 `gpt-6-sol`，独立于群聊模型。点击页面顶部模型名，在下拉菜单中直接选择 GPT 6 Sol 或 GPT 6 Astra，也可选「自定义模型」输入账号支持的新模型名称后保存，从下一轮生效，无需修改代码或重启；执行中的回合继续使用原模型，已有任务会话保留。设置存于维修室数据库的 `runtime.model_name`，验收摘要也使用该模型。保存只校验名称格式，账号是否支持由实际调用确认。

## 使用

1. 首次在电脑本机通过 `http://127.0.0.1:8080/repair` 打开，在「设备配对」里查看配对码。在手机维修室输入一次，以后保留设备 cookie。
2. 新建任务，选择近期生活背景的时间窗（默认两小时，每位最多 30 条）。默认只发给执行者，可手动切换为大家或另一位伴侣，持续讨论。
3. 查问题、找文件、在桌面等指定位置新建普通文档并写入内容，直接发消息给执行者即可。使用现有 Codex 的原生工具自主调查和执行，不向提示词预塞图片路径索引。关键信息无法查清时才询问。过程可见，可补充要求或停止。「＋」里的「继续处理 / 取文件」是快捷入口，输入框留空时接着上一条用户消息处理。
4. 需要修改小家功能、代码、配置或重启时，先在聊天里商量。执行者会把已经讲清楚的改动整理为当前约定；回复「就这样改」「按这个方案开始」或点击「开始」即可开工。确认针对实际看到的方案版本。新讨论会让旧方案失效。「当前约定」页保留为查看和手动编辑入口，不是必经步骤。普通文件新建不要求额外生成方案；不得擅自删除、清空、递归清理或覆盖重要内容，需先明确目标和影响并取得用户确认。
5. 正文进度、可读思路摘要、工具操作、输出和代码差异按时间显示在聊天中，不再设独立工作过程页签；命令与输出合并，详情默认折叠。顶部持续显示发送、排队、执行、等待新进展、断线或回合结束状态及运行计时。执行时可补充给执行者；改变范围先停止，再讨论确认。停止不会撤销已经发生的修改。
6. 回合结束后检查实际结果，在聊天末尾验收并回传群聊时，会额外调用当前配置的 Codex 模型，根据本任务的对话、状态和交付记录生成约 100–200 字的成果摘要。群聊仅显示一张摘要卡片，两位后续聊天读取同一段摘要；不再复制最后一条回复，也不把所有工具日志写入长期记忆库。摘要失败可重试；重复同步不重复发布，生成期间任务有新内容则需重新确认。

## 文件与模块

- `repair_store.py`：独立 SQLite 数据库、消息、事件、任务队列和方案版本。
- `repair_context.py`：人设、开发约定、独立任务历史和按角色过滤的近期私聊／群聊。生活背景限时限量；较长工作历史提供明确标记的早期节选，完整记录始终保存在数据库。执行者也可通过历史工具读取早期原文。
- `repair_dialogue.py`：聊天方案标记和明确确认语句识别。流式展示隐藏控制标记；可执行范围采用实际展示给用户的正文，模型无法仅凭隐藏代码块扩展范围。
- `repair_codex.py`：独立 App Server 工作会话。优先使用 PATH 中已安装的 Codex（本机为桌面附带的 CLI），找不到才回退到项目内 CLI；每轮及恢复旧会话时显式传入完全访问。认证复用现有登录，工作记录保存在专用 Codex home。名称规则和已有全局／项目 AGENTS.md 会加载；不声称自动继承桌面任务全部上下文、插件或工具。
- `repair_worker.py`：单实例后台工作进程。网页断线不取消；主网页服务重启不终止它；进程自身异常退出后将旧运行任务标记暂停，不自动重放修改。
- `repair_runtime.py`：维修室专用的轻量工作约定。关闭插件、连接器、技能搜索和多代理入口；每轮通过 Codex 的技能列表与配置接口禁用发现的额外技能，配置只写入维修室自己的 Codex home，不改桌面配置或技能文件。旧会话中的 Superpowers 流程明确不再适用；保留原生工具、项目约定、必要验证及原有范围确认。
- `repair_routes.py`：页面、设备配对、任务 API、附件上传／领取及成果回传。
- `repair_summary.py`：用户同步时的一次纯文本摘要调用，复用无本机执行工具的模型调用线路，最长等待 80 秒；只总结提供的工作记录，不继续执行维修。
- `static/repair.html`、`repair.css`、`repair.js`：独立页面和交互。
  页面复用小家的深浅色星空底图，消息为 13px 无边框文字。输入框和「＋」工具菜单保持紧凑，任务列表抽屉展开。输入框旁的图片按钮可选 PNG、JPG、WebP 截图，电脑支持粘贴截图；发送前展示可移除缩略图和上传状态，每条最多 4 个附件，上传完成才允许发送。模型执行期间仍只支持文字补充，图片在本轮结束后发送。
- `static/repair-result-card.js`、`.css`：群聊只读成果卡片，不添加任何维修触发提示。
- Android `RepairFileBridge.java`：普通附件下载，主 Activity 只注册一行桥接。

仅在 `main.py` 注册维修路由，在首页注册图标，在资源清单注册页面；群聊只增加卡片渲染挂点。原有聊天模型调用和权限配置不变。

## 运行

数据在 `aion-chat/data/repair-room/`：`repair.sqlite3`、`files/`、`codex-home/`、`worker.log`、设备配对文件。已有小家的 data 备份策略可一起覆盖。

首次提交工作时自动启动后台 worker，无新增网络监听端口。独立 worker 每次只执行一件事。日志和消息按游标增量读取，手机切回页面补读。

选择大家时，API 讨论回合最多等待 45 秒；连接或回复失败会显示是哪位未能完成回复，然后继续执行者的工作会话。只发给 API 伴侣时则报告失败，不擅自改发；用户停止会终止整个回合。默认执行者线路不经过 API 讨论回合。

经用户明确授权，维修室每轮使用 `danger-full-access` / `dangerFullAccess`，不再启动只读或仅项目可写的 Windows 受限沙箱，桌面和其他磁盘可按用户要求读写。删除和重要覆盖的确认属于工作指令约束，不是操作系统级禁止删除；完全访问会移除原有文件系统和网络沙箱限制。仍不继承桌面任务的工具管道和会话身份，桌面聊天历史不会自动搬入维修室。

网页后端新增路由需要重启主服务后生效。Android 普通文件保存需要安装包含新桥接的 APK；手机浏览器直接支持附件下载。旧版 App 可沿用图片保存桥接，普通文件会提示更新 App 或使用浏览器。

已确认方案包含「重启」时，执行者可使用专用重启工具。只支持本项目现有 `python main.py` 启动方式，检查进程创建时间和工作目录后再重启，不对所有 Python 进程执行终止。以 `--reload` 等其他方式运行时明确拒绝自动重启。主服务彻底不可访问时，手机也无法进入其维修页面。
