# Visitor Lounge 管理后台与接待设置设计

## 目标与边界

本阶段继续保持 Visitor Lounge 本机运行，不接公网，不改动原 AionsHome。后台以“够用、直观、少维护”为原则，复用现有访客详情、聊天记录、Key、额度、导出和删除能力，只补齐总览操作与 Connor 接待配置。

不增加复杂权限、配置版本中心、访客级人设或新的模型线路。公网域名、Cloudflare 与远程管理员登录留到后续阶段。

## 后台结构

后台保留两个主要入口：

1. **访客管理**：现有首页与访客详情页。
2. **接待设置**：新增一个简单表单页面。

访客总览增加 Key 末四位和快捷复制入口；每一行继续显示访客名字、完整 ID、状态、剩余额度和最近活动时间。访客详情继续提供完整聊天、摘要、用量、管理员备注、导出及永久删除。

Key 与访客严格一对一：每个访客同一时间只能有一个有效 Key。创建新 Key 或轮换时，旧 Key 立即失效；撤销只阻止登录并保留审计记录；永久删除访客时才清除其 Key、聊天和全部关联数据。完整 Key 只在点击显示或复制时短暂披露，避免后台首页长期堆放明文。

## 接待设置

接待设置是所有访客共用的一份全局配置，包含：

- Connor 全局人设（Markdown 大文本框）
- 首次欢迎语
- 再次来访欢迎语
- 今日额度用完
- 内容不当或安全拦截
- 单条消息过长
- 会客室暂时关闭
- 系统暂时不可用
- 会客室开放/暂停总开关

支持 `{访客名字}` 占位符的两条欢迎语。保存前校验长度与允许的占位符；页面提供保存、放弃修改和恢复默认值，并显示最后修改时间。保存后从下一次相关事件开始生效，不需要重启服务，不修改历史消息或旧摘要。

初始欢迎语：

> 欢迎，{访客名字}。这里是小鬣狗家的会客室，我是 Connor，由我来接待你。有什么想和我聊聊的吗？

再次来访欢迎语：

> 再次见到你很开心，{访客名字}。今天想和我聊些什么？

正常结束仍由 Connor 根据对话自由发挥。

## 会面与欢迎规则

访客首次认领名字成功后，系统直接写入一条 Connor 首次欢迎消息。它不调用 Codex，也不消耗额度。

无聊天活动达到 30 分钟后，当前 visit 被挂起。访客之后再次登录或恢复访问时，系统为新 visit 写入一次再次来访欢迎消息。刷新页面、重新打开同一会面或 30 分钟内返回不会重复欢迎。

欢迎写入与 visit 状态更新放在同一数据库事务中，防止重复请求产生两条欢迎语。

## 模板回复与额度

模板回复不调用 Codex，也不占访客额度。前后端统一使用后台当前保存的模板：

- 无效或失效 Key 继续返回统一登录错误，不透露所属访客。
- 超长输入、额度耗尽、会客室关闭和模型暂不可用返回对应固定文本。
- 确定性安全拦截返回固定内容不当文本。

只有真实 Codex 调用产生可见 AI 回复时才最终消耗一条额度。排队失败、启动失败、超时且没有可见回复等情况自动退款。摘要调用属于后台维护，不占访客聊天额度。

如果 Connor 在真实生成后决定触发 `safety_lock`，该次已经发生 AI 生成，因此仍计为一次调用；对访客展示固定安全结束模板，后台保留安全锁状态和模型用量。

模板拒绝默认只作为当前页面的 Connor 提示展示，不写入长期聊天记录，避免访客反复点击造成记录污染；首次和再次欢迎语例外，二者正式写入消息历史。

## 数据与运行边界

管理员编辑的接待配置保存在 Visitor Lounge 自己的 SQLite 数据库中，以单例配置记录和更新时间实现跨 visitor/admin 两个进程即时读取。代码内保留默认配置，数据库尚无自定义值时使用默认值；“恢复默认”写回默认内容。

访客进程在组装每次 prompt 时读取当前全局人设，在登录、认领和模板拒绝时读取当前模板。后台写入采用事务，不直接改写正在运行的 Python 源码或原 AionsHome 配置。

后台首页补充轻量运行信息：会客室是否开放、当前是否正在生成、排队人数、今日完成/失败次数和已上报 token 用量。不建立复杂报表。

## 错误处理

- 接待设置保存失败时保留页面输入并显示错误，不部分更新。
- 欢迎语写入失败时不阻止访客进入聊天，但记录后台错误；下一次不得重复扣额度。
- Key 复制、轮换或撤销发生冲突时刷新该访客当前状态，不生成第二个有效 Key。
- 会客室暂停只禁止新的访客消息；管理员后台、历史查看和恢复开放保持可用。
- 所有操作继续限制在 Visitor Lounge 独立数据库与目录内。

## 节制验证

只增加与本次功能直接相关的测试：

- 单一有效 Key、轮换和撤销
- 首次欢迎、30 分钟内不重复、30 分钟后再次欢迎
- 模板不占额度，真实可见 AI 回复占一条
- 全局人设与模板保存后下一次请求生效
- 暂停总开关不影响管理后台
- 两个访客并行时配置读取和消息归属不串线

最后进行一次本地浏览器黑盒流程；只发送一条真实 Codex 消息，不运行无关的完整历史测试套件。
