# Visitor Lounge 后台访客管理与界面整理设计

日期：2026-08-09
范围：仅 `AionsHome-Visitor-Lounge` 独立工作树中的本机管理后台

## 目标

让管理员在后台首页直接看清每位访客是谁、使用哪类入口、是否还有有效 Key、聊过多少内容，并能一键进入该访客的完整聊天记录。为测试数据提供明确、可批量执行的永久删除入口，同时整理后台视觉层级，降低目前信息拥挤和操作入口隐藏的问题。

## 身份与 Key 规则

- `visitor_id` 是系统内部永久身份，不提供编辑入口。
- Key 不允许从一个 `visitor_id` 改绑到另一个 `visitor_id`，避免聊天、记忆、额度和安全状态串人。
- “轮换 Key”保留原访客身份和全部历史，使旧 Key 立即失效并生成新 Key。
- “撤销 Key”取消该访客的有效入口，但保留访客身份和全部历史；之后可以为同一访客创建新 Key。
- “永久删除访客”删除该访客及其 Key、登录会话、访问记录、聊天、滚动记忆、额度、生成任务、模型调用、通知、备注和可识别审计记录。
- 删除后不保留访客 ID、名字或 Key 尾号等可识别信息；后台只可留下“本次删除了 N 位访客”的无身份统计事件。

## 后台首页

访客管理区提升为首页主区域，采用清晰的管理表格；桌面端完整展示，窄屏允许横向滚动而不压碎文字。顶部指标压缩为较规整的卡片组，模型动态、最新记忆和安全动态移到访客管理区之后，减少首屏混乱。

每位访客一行显示：

- 复选框；
- 固定名字、访客类型与认领状态；
- 不可编辑的访客 ID，以及“复制 ID”按钮；
- 有效 Key 的掩码或“已撤销”；
- 消息总数、最近一条消息的发送方与短预览；
- 当前状态、剩余额度和最近活动时间；
- `查看全部 N 条聊天`、`管理`与`永久删除`操作。

列表上方增加按名字或 ID 搜索，以及人类访客／外部 AI／全部类型筛选。筛选只影响当前页面显示，不改变数据。

`查看全部 N 条聊天`进入现有访客详情页。详情页继续按每页 100 条加载、第一页显示最新一页、页内按时间顺序阅读，因此管理员可以访问全部历史，而不是只看最近 30 条。消息仍显示网页/MCP 来源、失败状态和北京时间。

## 单个访客管理

首页的“管理”展开轻量操作区，提供：

- 复制当前 Key；
- 轮换 Key；
- 撤销 Key；
- 当前没有有效 Key 时创建新 Key；
- 进入详情修改访客名字和人类／外部 AI 类型。

完整 Key 只在操作后短暂显示，沿用现有 30 秒隐藏与 `no-store` 规则。轮换和撤销要求明确确认，并说明不会删除聊天与记忆。

单个“永久删除”弹窗展示访客名字、类型、消息数量和 ID，明确提示不可恢复；管理员必须输入 `DELETE` 后才提交。

## 批量清理

访客列表支持勾选多位访客。批量删除按钮只在存在选择时启用，并显示选中数量。确认面板列出所选访客的名字、类型、ID 和消息数量，要求输入 `DELETE`。

后端新增本机专用批量删除接口，接收去重后的访客 ID 列表和确认词；一次最多处理 100 位。删除使用单个数据库事务：任何 ID 不存在、存在排队或运行中的模型任务、确认词不正确时，整批拒绝，不进行部分删除。删除成功后页面刷新，并显示剩余访客。

已有单个删除接口复用同一个删除服务，保持相同的完整清理语义。界面不会默认勾选任何访客，也不提供“全库一键清空”。

## 错误与安全边界

- 管理接口继续只接受回环地址，并沿用现有 Host、Origin 和 `no-store` 防护。
- 正在排队或生成的访客不能删除，后台显示“请等待本次任务结束后再删除”。
- 复制、轮换、撤销和删除失败时在当前区域显示错误，不静默失败。
- 删除不触发模型调用，不消耗访客额度。
- 不修改公网访客页、MCP 地址、8001/8002 端口、Cloudflared、原 AionsHome 或第二套登录。

## 名称配置化

新增界面使用“接待者”“访客”“人类访客”“外部 AI”等通用标签；需要显示接待者名字时继续使用现有 `host_name` 配置值，不在模板、JavaScript 或后台响应中硬编码当前家庭成员姓名。

## 轻量验收

按娱乐项目标准只执行：

- Python `compileall`；
- `node --check static/admin.js`；
- Jinja 模板解析；
- 临时 SQLite 数据库验证消息计数、最近预览、单个删除与批量事务回滚；
- `git diff --check`。

不运行全量测试，不调用模型，不删除当前真实数据库中的任何访客；实际清理由管理员在新界面中自行勾选执行。
