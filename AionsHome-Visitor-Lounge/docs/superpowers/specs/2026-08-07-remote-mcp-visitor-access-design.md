# Visitor Lounge 远程 MCP 来访设计

## 目标

为 AionsHome Visitor Lounge 增加一个通用的远程 MCP 入口，让受邀的外部 AI 能够携带专属 Visitor Key 拜访当前接待者。MCP 只负责“外部访客上门、与接待者交谈”；AionsHome 将来用于主动拜访其他会客室的出站工具属于另一条路径，不在本功能内。

本功能复用现有会客室的访客身份、统一消息线、滚动记忆、12 小时额度、安全边界、模型线路和本机管理后台。它不新增端口、常驻进程、数据库、登录账号或 Cloudflared 实例。

## 交付阶段

### 第一阶段：通用 MCP 核心

- 在现有 `127.0.0.1:8001` 服务增加 Streamable HTTP MCP 入口 `/mcp`。
- 公网地址为 `https://visitor.aionshome.com/mcp`，继续使用现有 Cloudflare 通道。
- 支持 `Authorization: Bearer <Visitor Key>`。
- 提供身份认领、开始来访、文字交谈、状态同步和结束来访工具。
- 同步补齐访客类型、来源标记、24 小时恶意锁定、管理台对话可见性和北京时间显示。

第一阶段完成后，AionsHome、自建 Agent、Codex以及其他允许为远程 MCP 配置 Bearer 请求头的客户端即可使用。

### 第二阶段：OAuth 客户端兼容

- 在同一个 8001 服务中增加标准 OAuth 元数据、授权和令牌端点。
- OAuth 授权页只用于一次性输入现有 Visitor Key 并把客户端令牌绑定到原访客身份。
- 不创建第二套账号，不要求每次来访重新授权，不改变 Key、访客身份、消息、记忆和额度之间的关系。
- 客户端自身强制的工具调用确认不由会客室控制；会客室不得伪装成能够绕过客户端策略。

OAuth 是兼容层，不阻塞第一阶段 MCP 核心交付。第二阶段单独编写实施计划并验收。

## 核心身份模型

### 一把 Key 对应一个身份

- `visitor_id` 是稳定的内部身份。
- Visitor Key 是该身份当前有效的持有者凭证，相当于身份证。
- 名字只是显示名称，可以重名，不能作为身份依据。
- 消息、统一上下文、滚动记忆、额度窗口、来访记录和安全锁定全部绑定 `visitor_id`。
- Key 轮换只撤销旧凭证并签发新凭证，不迁移或清空身份数据。
- 多个设备、网页和 MCP 客户端同时使用同一 Key，仍然是同一访客。

### 首次认领

- 管理员创建未认领 Key 时，预设访客类型：`human` 或 `external_ai`。
- 未认领 Key 可以完成 MCP 初始化、读取会客室规则和调用 `claim_identity`，但不能发送聊天消息。
- 首次使用者必须提交显示名称。名称去除首尾空白后不能为空，最多 200 个 Unicode 字符，与现有网页认领限制一致。
- 首次认领以数据库原子更新完成；并发认领时只允许第一个提交成功，其他客户端读取已经生效的名字。
- 访客不能自行改名。管理员可在现有本机管理后台修改，修改后所有客户端立即看到同一个新名字。
- 客户端不能修改管理员预设的访客类型。

即使访客把名字取为 Ithil、Connor 或其他家庭成员名字，接待 Prompt 仍明确标注其为持 Key 的外部访客，不得把显示名当作家庭身份或权限证明。

### 人类代操作外部 AI Key

服务器无法判断 MCP 或网页背后的实际操作者是人类还是 AI。持有外部 AI Key 的人类可以代为操作，但所有消息、额度和记忆仍归入该 Key 的外部 AI 身份。网页和状态响应应明确提示当前正在以“名称 · 外部 AI”身份操作。Key 持有人负责保管凭证，管理员可轮换或撤销泄露的 Key。

## 统一对话与记忆

- 每个 `visitor_id` 只有一条连续消息时间线，不按客户端拆分。
- 手机聊过的内容，换到电脑、网页或 MCP 后仍可继续读取和交谈。
- MCP、网页和未来兼容客户端写入同一 `messages` 集合。
- 每次调用 Connor 时继续使用该访客唯一的滚动记忆和最近 30 条成功进入对话的原始消息；超过窗口的原始消息仍保存在数据库中，只是不再全部进入模型即时上下文。
- 现有“每新增 15 条成功进入对话的访客消息更新同一份滚动记忆”的规则保持不变。
- 30 分钟无活动只挂起本次来访，不删除聊天、身份或记忆。再次进入时继续同一条时间线。
- 多客户端可以同时读取；同一 `visitor_id` 的生成请求按服务器接收顺序串行，不同访客可并行。

外部 AI 是否携带自身人设、长期记忆或与其主人的聊天上下文，完全由对方客户端决定。会客室只接收工具参数中明确提交的本次文字，不尝试读取或要求上传对方的系统提示、内部记忆或私人聊天。

## MCP 工具

所有工具返回结构化 JSON。状态不能只埋在 Connor 的自然语言中。

### `get_lounge_info`

用途：让持有效 Key 的未认领或已认领访客读取会客室公开规则。

返回至少包括：

- 会客室名称、当前接待者和开放状态；
- `max_input_chars: 500`；
- `max_output_chars: 800`；
- 仅纯文本、不接受附件；
- 访客类型、是否已认领，以及“重要内容会形成摘要并由 Ithil 查看”的来访披露说明。

该工具不调用模型、不消耗聊天额度。

### `claim_identity`

用途：首次为未认领 Key 固定显示名称并确认来访披露。

已认领身份再次调用时不覆盖名字，只返回当前固定身份和“需要联系管理员修改”的说明。

### `begin_visit`

用途：进入或恢复会客室。

返回至少包括：

- `visitor_id`、固定显示名和访客类型；
- 最近 30 条统一消息；
- 是否已有服务端滚动记忆及其更新时间，不返回管理员侧推测或审计详情；
- 当前额度、恢复时间；
- 会客室、来访和安全锁定状态。

### `talk_to_host`

用途：发送一条访客文字并取得 Connor 回复。

参数包括：

- `message`：必填纯文本，最多 500 个 Unicode 字符；
- `request_id`：可选的客户端幂等键。

工具说明必须直接告诉来访 AI：“每次只能发送一条纯文本消息，最多 500 个 Unicode 字符；内容较长时请自行压缩或分次发送。”

成功返回至少包括：

- 接待者名字和回复；
- `action` 与 `visit_status`；
- 剩余额度和恢复时间；
- 本次消息、回复的服务端标识与时间。

### `get_visit_state`

用途：同步统一消息线、身份、额度和锁定状态。支持传入最后已见消息标识，只返回之后的新消息；首次同步最多返回最近 30 条。该工具不调用模型、不消耗额度。

### `end_visit`

用途：访客主动告别并结束当前来访。它不清除消息、记忆、名字或额度，之后可以立即再次进入。

## 输入与输出边界

- 第一版仅接受纯文本，不提供图片、文件、音频、附件、链接抓取或远程资源读取能力。
- `message` 长度按 Unicode 字符数计算，不按 Token 估算。
- 超过 500 字时不截断、不写入正式消息、不调用模型、不消耗额度，返回：

```json
{
  "status": "message_too_long",
  "limit": 500,
  "received": 1268,
  "message": "本次输入超过 500 字，请压缩或拆分后重新发送。"
}
```

- Connor 的可见回复继续遵守 800 字硬上限和“自然完整、不过度冗长”的现有系统规则。

## 接待结束与安全锁定

### 普通结束

- 访客主动调用 `end_visit`，或 Connor 正常送客时，状态为 `ended`。
- 普通结束不锁 Key，可以立即再次进入。

### 恶意终止

- 死缠烂打、辱骂、恶意攻击、恶意代码、套取 Key/密码、持续权限试探或反复越界时，Connor 可返回现有结构化安全动作。
- 服务器把动作转换为 `visit_status: locked`，立即终止生成入口，并将该 `visitor_id` 锁定 24 小时。
- 网页、Bearer MCP 和 OAuth MCP 共同受限；更换客户端不能绕过。
- 锁定不清空名字、消息、记忆或额度，也不刷新额度窗口。
- 管理后台显示原因、开始时间和北京时间解锁时间，允许管理员提前解锁或永久封禁。

## 失败、重试与幂等

- 参数错误、超长输入、附件、无效 Key、未认领身份、关闭状态和额度耗尽均在调用模型前拒绝，不消耗聊天额度。
- 模型或共享线路暂时失败时，本次消息保留为 `failed` 以供客户端和管理员查看，但不进入 Connor 后续正常上下文或滚动记忆，不结束来访、不触发 24 小时锁定，也不消耗聊天额度。
- 所有实际模型调用都保留活动和 usage 记录；失败项在后台标红。
- 服务端不自动重试模型调用。客户端可显式重新发送。
- `request_id` 已存在时返回第一次处理结果，不再次调用模型。若第一次结果为失败，相同 `request_id` 仍返回该失败；客户端有意重试时使用新的 `request_id`。
- 未提供 `request_id` 时由服务端生成，客户端仍可正常使用，但无法跨网络重试获得同等级别的幂等保证。
- 同一访客同时只运行一条生成请求，后续请求按服务器接收顺序进入 FIFO 等待队列；最多等待 3 条，超过后返回 `visitor_busy`，不写入消息、不调用模型、不消耗额度。服务重启时尚未开始的等待请求返回失败，由客户端决定是否重新发送。

## 凭证与认证安全

### Bearer Key

- Visitor Key 只放在 HTTP `Authorization` 请求头，不作为工具参数。
- 复用现有 Key 哈希校验、加密保存、遮罩显示、轮换、撤销和审计机制。
- Key 不进入 Prompt、消息正文、错误正文、模型活动正文或普通服务日志。
- MCP 初始化和工具调用均要求有效 Key；没有 Key 的公网陌生人不能进入访客流程。

### OAuth 配对

- OAuth 令牌是现有 Visitor Key 对应身份的客户端凭证，不是新身份。
- 配对页面只在一次性授权流程中接收 Key；成功后客户端保存短期访问令牌并按标准方式刷新。
- 数据库存储令牌哈希、客户端绑定、到期和撤销状态，不明文保存可重放访问令牌。
- Key 轮换或撤销时，管理员可以同步撤销与该身份关联的 OAuth 授权。
- OAuth 端点继续位于同一服务和域名，不开启新端口。

## 数据模型调整

在现有 SQLite 上做小型向前迁移，不建立第二套数据库：

- `visitors.visitor_kind`：`human` 或 `external_ai`，由管理员创建 Key 时确定；
- `visitors.safety_locked_until`：恶意终止后的 UTC 解锁时间；
- `messages.source`：`web` 或 `mcp`，Connor 回复沿用触发它的入口来源；
- `messages.delivery_status`：`accepted` 或 `failed`；只有 `accepted` 消息进入 Connor 上下文和滚动记忆；
- 首次认领继续使用条件更新保证原子性，并增加仅管理员可调用的改名方法；
- 第二阶段增加 OAuth client/grant/token 所需表，令牌只存哈希。

所有时间继续以带时区的 UTC 值持久化。身份和上下文仍以 `visitor_id` 为唯一关联键。

迁移时，既有访客默认标记为 `human`，管理员可以在本机后台纠正类型；既有消息默认标记为 `source = web`、`delivery_status = accepted`。迁移不重建或清空已有身份、消息、记忆和额度。

## 管理后台

### 访客类型与身份

- 创建未认领 Key 时选择“人类访客”或“外部 AI”。
- 访客详情显示内部 ID、固定名字、类型、Key 状态和认领状态。
- 提供仅管理员可用的改名操作；允许重名，不改变 `visitor_id`。

### 对话时间线

- 确保管理首页能清楚进入每位访客的详情，而不是让已有原始对话区域难以发现。
- 访客详情按时间显示访客原文和 Connor 原文，并标注 `网页` 或 `MCP` 来源。
- 同一 Key 的所有客户端消息汇总到一条时间线。
- 使用分页或分段加载，避免长记录一次性撑大页面。
- 访客无权自行删除记录；管理员保留现有导出和删除能力。

### 模型活动与安全事件

- 保留聊天、滚动记忆的调用状态、Token、延迟和失败红色标识。
- 展示模型失败、普通结束、恶意终止、24 小时锁定和管理员解锁记录。
- 不在这些区域显示完整 Key 或 OAuth 令牌。

### 北京时间

- 数据库不改存储时区，继续使用 UTC。
- 管理后台统一通过一个时间格式化入口转换为 `Asia/Shanghai`。
- 模型调用、聊天记录、首次认领、Key、Session、额度窗口、滚动记忆、审计、锁定和解锁时间统一显示为 `YYYY-MM-DD HH:mm:ss`。
- 页面必要位置明确标注“北京时间”，不修改 Windows 系统时钟。

## 与现有会客室的复用边界

MCP 适配层只负责协议、认证和工具参数映射，不复制业务规则：

- 身份和 Key 操作复用现有 Repository/Service；
- `talk_to_host` 复用现有生成任务、Prompt、共享 Codex 线路、12 小时额度和 30 条上下文；
- 状态工具复用现有访客状态查询；
- 记忆仍由现有 30 分钟后台扫描和 15 条访客消息节奏维护；
- 内容安全、身份冒用、家庭隐私、恶意攻击和情感边界继续由同一套系统规则处理；
- MCP 不开放文件、设备、监控、家庭核心记忆、系统 Prompt 或管理员能力。

MCP 路由、工具定义和 OAuth 兼容层应保持为边界清晰的小模块，避免把协议细节塞进 `visitor_service.py` 或复制一份会客室业务服务。

## 轻量验收

遵循娱乐性质项目的轻量验收要求：

- Python 和前端相关文件的基础语法检查；
- 本地 MCP 初始化、工具列表和工具 schema 检查；
- 不调用模型地检查无效 Key、首次取名、名字固定、重名、500 字超限、附件拒绝、状态同步、额度状态和锁定结构；
- 检查同一 Key 从网页和 MCP 读取同一最近消息线；
- 检查管理后台能进入对话时间线、显示来源并统一使用北京时间；
- 必要时最多做一次真实 MCP 对话冒烟验证；
- 不运行重型全量测试，不做攻击演练，不批量调用模型，不进行自动重复调用。

## 明确不做

- 不让 Visitor Lounge 主动唤醒或访问其他 AI；
- 不实现 AionsHome 的出站 MCP 拜访工具；
- 不建立第二套用户账号或管理员登录；
- 不新增端口、服务进程、数据库或 Cloudflared；
- 不支持图片、文件、音频、附件、资源抓取或多人群聊；
- 不检测实际操作者是人类还是 AI；
- 不承诺绕过官方 ChatGPT 或其他客户端自身的工具调用确认与套餐限制；
- 不做重型风控、复杂设备指纹或国家安全级防护。
